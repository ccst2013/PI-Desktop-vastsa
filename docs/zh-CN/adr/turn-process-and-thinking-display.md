# ADR turn-process-and-thinking-display：回合过程与思考展示

## 背景

模型在回答一次用户请求之前，可能多次交替输出推理、工具调用和进度文字。仅使用分散
的活动组，会让进度文字与最终回答处于同一视觉层级；仅使用一个扁平的过程容器，又会
让较长的工具或搜索序列难以浏览。部分用户还需要稳定的思考状态提示，而不是快速变化
的推理正文。

## 决策

所有已加载的助手回合条目都使用同一套回合过程展示：投影为一个可折叠的过程披露，
以及其后的最终回答。思考、工具、中间进度文字以及该回合的 `Bash` 命令行都按转录顺序
保留在这个披露内。流式输出时，暂定为回答的末尾助手文字保持可见；如果随后出现工具或
思考活动，该文字会移入过程，但不会改写已存消息。`UiMessage` 没有语义化的最终回答标记，
因此渲染器不根据措辞猜测。用户消息、系统消息和压缩分隔线继续保留原有回合边界。

每个回合只渲染一个过程披露。回合在给出答案之前产生的所有行都位于其中——活动组与 `Bash`
命令行同样如此——因此长回合可以用一次操作收起，而不会在答案上方留下一列并列披露。答案本身
位于披露之外。

在该披露内部，非 Bash 活动形成普通活动组：两个进度段落或命令行之间的一段连续工具、搜索或
思考活动，并且仅在当前思考偏好下至少有两个可见项时出现。单项活动直接使用自身披露；被隐藏的
思考不会制造多余的组包装。现有 Task 拓扑仍是其片段的容器，不会在普通活动组中重复渲染。

命令行位于其组内还是组旁，由 `keepCommandsExpanded` 偏好决定，默认开启。开启时，`Bash`
和 run 别名会从所处的组中提取出来：各自成为披露顶层的独立行，相邻调用保持分离，详情在用户
打开之前保持收起。关闭时，命令行保留在流程中的原位置，读起来就是所在组的另一行——即命令尚未
被分离之前的布局。该偏好不会改变回合渲染的披露数量：两种取值都只渲染一个。

活动组的折叠默认值是统一的，不依赖思考偏好或上述偏好。拥有当前执行片段的普通活动组默认展开，
仅在用户未操作时于完成后收起；其他已完成组默认收起。只要活动组中记录过失败或被拒工具，
尚未被用户接管的活动组就会在后续恢复期间保持展开，并在回合完成后收起。关闭回合披露会一并
关闭其下的组，重新展开则恢复用户此前展开过的组。

回合披露的标题只陈述回合的结果，绝不回显正在处理的具体项，因为一条 shell 命令或搜索词可能
任意长。其取值优先级依次为失败、已停止、执行中、已完成：已记录的失败优先于停止，因为该回合
没有产出答案，而看起来正常的标题会掩盖这一点。停止取自被中止的消息，这是运行时唯一记录的信
号——回合结果只区分完成与失败。工具或思考仍在执行时，被中止的活动行同样记录停止；委派子任务
的行不决定父回合结果。执行期间，用户可能长时间停留的阶段（压缩上下文、恢复）会各自
命名；当前步骤为推理时显示 `Thinking`，瞬时阶段则显示为普通执行中。转录未记录时间时不显示
时长，而不是显示为零；问题计数与标签并列显示。

披露与它展开的层级共用同一条左边缘。层级由字号与颜色表达，而不是缩进，因此嵌套的组标题与
命令行起始位置与回合标题完全一致。

思考偏好是一个布尔值 `showThinking`。当它为 false 时，活动思考指示器保持可见，而已完成
的思考行和摘要会被隐藏，空的纯思考容器会被省略；已存推理仍会保留，因此重新打开该偏好
会恢复已完成的思考行和摘要。被隐藏的思考不会制造空的组包装。

本决策早先引入的叶子默认值后来被移除。条目载荷都不会自动展开：工具调用、托管搜索或
计划行在用户打开之前始终只是标题行，无论它位于活动组的哪一项，且与思考偏好无关。
组默认值不变，打开一个已收起的祖先仍会恢复已保留的条目选择，不会展开所有后代。

每个标题只切换自己的层级。父子状态彼此独立：收起父级会保留后代选择，重新展开会恢复
这些选择，同级组不是互斥手风琴。用户操作某个条目时，会把所属组标记为用户接管，但不会
切换该组；完成事件不得收起包含用户已展开、聚焦或选择内容的容器。只要所属的保留会话
窗格仍存在，手动选择就跨流式更新、完成、偏好切换、单项变组和行重新挂载保留。窗格淘汰、
会话删除或渲染器重启会释放这些展示状态；它们不写入消息或宿主设置。

搜索和导航只展开目标所需的祖先路径：拥有该消息的回合过程和活动组。条目级精确定位不在
本次范围内，各行详情仍由各自的折叠控制。同一请求重新渲染时，不会反复覆盖用户之后的
手动收起。被偏好隐藏的推理会保持隐藏，直到用户打开 `showThinking`。助手错误、中止后的
末尾部分回答、权限／提问／计划／目标决策及其他待处理操作面必须位于隐藏过程之外，
无需展开过程即可操作。

“设置 -> AI -> 默认项”提供一个 `Show thinking` 布尔开关，以可选的 `showThinking`
`AppSettings` 字段持久化。缺失或非布尔值会回退到旧版 `thinkingDisplayMode` 字段：
显式 `compact` 隐藏推理，而 `detailed`、未知值或缺失值都显示推理。旧字段为持久化设置的
兼容性而保留，不再在界面中暴露。该偏好只改变展示，不改变提供商思考级别、运行时或模型
上下文、已存推理、导出、权限、执行或复制载荷，也不控制回合过程或活动组的折叠。过程标题
使用已记录的计时、直接工具／搜索计数、运行状态和问题计数；不会重复计算委派子任务，
也不会把单个失败工具误报为整个助手回合失败。

## 结果

- 每个回合一个披露，让最终回答与待处理操作保持可达，并使长回合可以用一次操作收起。
- 活动组的折叠默认值统一：运行中的工作保持可见，未操作的已完成组默认收起，无论思考偏好如何
  都保留用户明确的披露选择。关闭回合披露会关闭其下的组，重新展开则恢复用户此前展开过的组。
- 当 `showThinking` 为 false 时，活动指示器保持可见，而已完成的推理行和摘要被隐藏。
  已存推理仍会保留，重新打开偏好时重新出现。
- 当 `keepCommandsExpanded` 开启（默认）时，run 别名作为独立行渲染，命令密集的回合保持易读；
  关闭时恢复较早的布局，命令行读起来就是所在组的另一行。两种取值都不改变披露数量；该偏好
  在渲染时读取而非在构建条目时读取，因此切换后立即重绘，而无需等待新消息。
- 标题用一行说明回合的结果。回显当前命令的做法已被移除：它会把计数挤出该行，并且与打开该项
  已经能看到的内容重复。
- 披露记忆是以稳定回合、组和条目标识为键的窗格展示状态，不是持久化转录契约，也不
  属于中央工作流 store。
- 只对已加载的转录条目分组；不会重建未加载历史，也不会跨压缩边界合并回合。
